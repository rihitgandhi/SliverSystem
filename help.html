Getting started

AccessAI's browser extensions are grounded in the WCAG principles below and built to fit into how you already browse — no separate workflow to learn. A typical path looks like:

  1. Try Second Brain — it remembers your reading and display preferences across sites so you never re-configure them. See the Second Brain section below.
  2. Try Voice Navigation — control any site by voice instead of a mouse or keyboard. See the Voice Navigation section below.

Privacy note. Both extensions are designed to keep your data on-device by default — see each tool's own Trust & control section for specifics.

WCAG cheat sheet

The four POUR principles underpin every WCAG criterion, and every AccessAI tool is designed against them.

Perceivable

Alt text, captions, color contrast (4.5:1 for body text AA), responsive layout.

Operable

Keyboard access, no keyboard traps, visible focus, target sizes, no seizure-inducing motion.

Understandable

Plain language, predictable interaction, clear error messages, consistent navigation.

Robust

Valid HTML, correct ARIA, compatible with assistive tech across browsers.

Common Level AA targets

  • 1.1.1 Non-text Content — every image needs alt text (or empty alt if decorative).
  • 1.4.3 Contrast — 4.5:1 for normal text, 3:1 for large text and UI components.
  • 2.1.1 Keyboard — all functionality available without a mouse.
  • 2.4.7 Focus Visible — keyboard focus indicator must be clearly visible.
  • 3.3.2 Labels or Instructions — form inputs need visible labels.
  • 4.1.2 Name, Role, Value — custom widgets need correct ARIA semantics.

Troubleshooting & FAQ

Second Brain says preferences aren't carrying over — what's wrong?

Check that you haven't cleared your data via the Trust & control panel's "Clear" button, and that you're testing on the same browser profile — stored preferences are scoped per-browser, not synced to an account.

Does Voice Navigation need an internet connection?

Voice command recognition and mapping rely on the AccessAI backend, so yes — an active connection is required for commands to be understood and executed.

Can I use these tools on private or authenticated pages?

Both tools run entirely client-side against whatever page is currently open in your browser — including pages behind a login — since neither needs to fetch the page from a server.

How do I report a bug or request a feature?

Include the page you were on, the steps that led to the problem, and what you expected to happen instead — that's the fastest path to a fix.
